## Precedence

Lowest to highest, the last writer wins:

1. **Built-in defaults** — registered in `setDefaults`
   ([`config.go:190-209`](../internal/config/config.go)) and `setGCDefaults`
   ([`gc.go:83-96`](../internal/config/gc.go)).
2. **`.quasar.yaml`** — read by viper. The single-repo entry point is
   `config.Load` ([`config.go:162-164`](../internal/config/config.go)); the
   file is located by `initConfig`
   ([`cmd/root.go:59-77`](../cmd/root.go)).
3. **Environment variables** (`QUASAR_*`) — `viper.SetEnvPrefix("QUASAR")` +
   `viper.AutomaticEnv()` ([`cmd/root.go:72-73`](../cmd/root.go)) make every
   `QUASAR_<KEY>` override the file value for `<key>`.
4. **CLI flags** (highest) — bound on the root command; e.g. `--verbose`
   ([`cmd/root.go:56`](../cmd/root.go)).

A missing config file is not an error: `initConfig` ignores the
`viper.ReadInConfig()` error and falls back to defaults
([`cmd/root.go:75-76`](../cmd/root.go)).

## Global vs per-repo `.quasar.yaml`

There are two distinct load paths, and they read different parts of the file:

| Path | Loader | What it reads | Used by |
|------|--------|---------------|---------|
| **Global** | `config.Load` ([`config.go:162`](../internal/config/config.go)) | the whole `Config` struct from the process-wide viper instance | single-repo subcommands via `initConfig` ([`cmd/root.go:59`](../cmd/root.go)) |
| **Per-repo** | `config.LoadFromPath` ([`config.go:179`](../internal/config/config.go)) | an *isolated* viper instance over one repo's `.quasar.yaml` | the multi-repo runtime via `repoPreCommitFor` ([`cmd/fleet.go:184-200`](../cmd/fleet.go)), which extracts only the `[pre_commit]` block |

`initConfig` searches the current directory first, then the user's home
directory ([`cmd/root.go:63-69`](../cmd/root.go)), so a global `~/.quasar.yaml`
provides defaults and a `./.quasar.yaml` in the repo overrides them. The
per-repo path is explicit: `repoPreCommitFor` joins `<repoPath>/.quasar.yaml`
and treats a missing file as "no pre-commit gate," not an error
([`cmd/fleet.go:188-191`](../cmd/fleet.go)).

`config.Default` ([`config.go:171`](../internal/config/config.go)) returns the
built-in defaults with no file at all, so "no file" and "empty file" converge.

## Per-sensor TOML

Sensors are configured **not** in `.quasar.yaml` but as one TOML file per
instance under `<repo>/sensors/<name>.toml`. The decode target is `sensorFile`
([`internal/artifacts/loader_health.go:29-40`](../internal/artifacts/loader_health.go)):
`name`, `type`, `poll_interval`, `max_inflight`, a `[config]` block, and
`[[triggers]]` (`constellation`, `when`). See
[sensor-authoring.md](sensor-authoring.md) for the full schema and a worked
example, and [sensors.md](sensors.md) for the model.

## Per-nebula TOML

A nebula's manifest lives at `<repo>/.nebulas/<id>/nebula.toml`, not in
`.quasar.yaml`. Sections: `[nebula]`, `[defaults]`, `[execution]`, `[context]`,
`[dependencies]`. The `gate` field is **removed** — `trust` (autorun) is the
only supported mode going forward. See the "Nebula Authoring" section of
[CLAUDE.md](../CLAUDE.md) for the field-by-field manifest reference and
[architecture.md](architecture.md) for the nebula model.

## Per-star `[health]`

The `[health]` block is a **per-star** knob in a star's Markdown frontmatter
(`internal/artifacts/defaults/stars/<name>.md`), parsed by `parseStarHealth`
([`internal/artifacts/loader_health.go:46-72`](../internal/artifacts/loader_health.go))
— it is *not* a `.quasar.yaml` key. It configures the dead-coder healthcheck
(`wall_clock_cap`, `file_write_idle_cap`, `token_rate_window`,
`token_rate_floor`, `tool_call_ratio_ceiling`, `tool_call_window`,
`cpu_idle_cap`). See the healthcheck section of [runtime.md](runtime.md).

## Token resolution

Secrets are **never** inlined in `.quasar.yaml`: any key named `token`
(case-insensitive, at any depth) is a config-load error — `ErrInlineToken`,
enforced by `checkInlineTokens` ([`config.go:157`](../internal/config/config.go),
[`config.go:260-276`](../internal/config/config.go)). Supply credentials via
`token_env` or `token_file` instead.

A secret spec resolves with this precedence (`ResolveSecret`,
[`internal/sensors/secret.go:56-82`](../internal/sensors/secret.go)):

1. **`token_file`** (highest) — read from the file, supporting Docker
   `--secret` mounts. On Unix the file **must** be mode `0600` or `0400`; a
   looser mode yields `SecretLooseError`. A configured-but-broken `token_file`
   is a **terminal error** — there is no fallback to the env var, so a
   misconfigured container fails loudly.
2. **`token_env`** — read from the named environment variable (12-factor).
3. **Empty string** — neither set; downstream tools (e.g. `gh`) fall back to
   their own auth chain.

See [sensors.md](sensors.md) for how the GitHub sensor consumes a resolved
token.
