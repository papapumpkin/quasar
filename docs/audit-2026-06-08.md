# Codebase Audit — 2026-06-08

A multi-pass audit of dead code, unimplemented-but-claimed features, fabric DB
usage, and event-bus wiring. Surgical fixes were applied in the same session;
structural gaps that need their own scoped work are catalogued below.

## Method

Four parallel discovery passes:

1. **Entanglement lifecycle reality check** — verify the six-status lifecycle
   (declared → claimed → in_flight → fulfilled | withdrawn | deprecated)
   spec'd in `.nebulas/coordinated-parallel-execution/00-entanglement-lifecycle.md`
   is wired to real runtime events, not just defined in the store.
2. **Event bus firing vs swallowing** — map every `bus.Kind*` to its
   publishers and subscribers; flag orphans and ghosts.
3. **Fabric DB table/column usage** — for every table and column in the
   migrations, find writers and readers; flag write-only, read-only, and
   never-populated.
4. **Spec-vs-reality on shipped nebulas** — for each phase marked `done`,
   sample acceptance criteria and verify on disk.

## Structural gaps

The audit originally flagged four gaps for follow-up nebulas. The 2026-06-08
session also fixed three of them in-place; only the multi-repo Runtime
wiring (the consumption *site* for trigger_queue) remains as future work.

### A. `trigger_queue` consumer — fully closed

**Symptom (now historical):** The TUI fleet view's `Store.Approve` inserted
rows into `trigger_queue` (`internal/tui/fleet/fleet.go:344-353`) that piled
up until the GC swept them, because nothing in the runtime consumed them.

**Fix shipped this session:**
- `internal/constellations/supervisor.go` — `Supervisor` with `Tick` and
  `Run`, a `Firer` interface (now takes `repoPath` so multi-repo
  implementations can route), oldest-first claim of pending rows, atomic
  mark-consumed-before-fire so a crashed Fire is never double-fired,
  bounded batch size, and a fail-fast pattern that marks failed rows
  consumed-with-log rather than retrying forever on the same bad input.
- `internal/constellations/supervisor_test.go` — seven tests covering
  fire ordering, batch limit, failure handling, empty queue, double-claim
  safety, oldest-first, and the new repo_path forwarding.
- `internal/constellations/runtime_cache.go` — `RuntimeCache` lazily
  constructs and memoizes one `*Runtime` per repo path. Shared resources
  (DB stores, blobstore, claude invoker) are built once; per-repo
  resources (artifacts.Loader, gitops.Client, workDir, pre-commit
  policy) are derived on first Get. `RuntimeCacheFirer` adapts the cache
  to the `Firer` interface; `SingleRepoFirer` adapts a single Runtime
  for tests / single-repo callers.
- `internal/constellations/runtime_cache_test.go` — covers DB-required
  validation, empty-path rejection, success memoization, per-repo
  isolation, PreCommitFor invocation per-repo, and the RuntimeCacheFirer
  routing path.
- `cmd/fleet.go` — `startTriggerSupervisor` constructs a per-repo
  Runtime cache from the live fabric DB + claude invoker + per-repo
  `.quasar.yaml` lookup, spins the Supervisor in a goroutine for the
  lifetime of the dashboard, and routes its diagnostics to
  `.quasar/supervisor.log` so they don't corrupt the Bubble Tea
  altscreen. Failures during construction (no claude, no blobstore,
  bad config) are best-effort: the dashboard still opens, the operator
  sees a single stderr line, and the supervisor is simply disabled for
  that session.

**Net effect:** Fleet approvals now actually fire the named constellation
against the per-repo Runtime within ~1s. The chain
`fleet.Approve → trigger_queue → Supervisor.Tick → Runtime.Fire` is
end-to-end functional.

### C. `gc_runs` audit extension — shipped this session

`quasar gc audit --since <duration>` now walks `gc_runs` in addition to
the JSONL log and prints a per-category summary: passes, swept_count
totals, reclaimed_bytes, error count, last_started timestamp. The JSONL
log still carries fine-grained per-action entries; `gc_runs` is the
aggregate trend view. Both render in the same audit command output.

Implementation: new `printGCRunsSummary` helper in `cmd/gc.go`. Read-only;
opens its own fabric handle and closes it. Empty windows render a
"ledger empty" line rather than the table.

### D. `PhaseTracker.Collisions()` — already wired (audit was wrong)

`internal/nebula/worker.go:147` defines `publishCollisions` which is
called every iteration of the main worker loop (line 421). It populates a
`bus.CollisionPayload` slice from `wg.tracker.Collisions(ids)` and
publishes a `KindEntanglementUpdate` event with `Collisions` set. There
is also a `TestPublishCollisions` and `TestPublishCollisions_NilBus`
covering the wiring.

The audit's claim that "TUI doesn't import PhaseTracker" was true but
irrelevant — the data flows through the bus, which is the correct
architecture for the DB-only/bus-only TUI. No fix needed.

### E. Bus `Publish` errors swallowed everywhere

12+ sites use `_ = bus.Publish(...)`. The audit confirms this is
intentional (fire-and-forget messaging — bus failures should not crash the
orchestrator). No fix recommended; this is by design.
